# QA Test: Demoblaze — добавление Samsung Galaxy S6 в корзину

Автоматизированный тест-кейс на **Playwright (Python)**, который проверяет сценарий добавления товара в корзину на сайте [demoblaze.com](https://www.demoblaze.com/).

Проект создан в рамках тестового задания по QA-автоматизации.

## Сценарий теста

1. Открыть страницу https://www.demoblaze.com/
2. Нажать на товар **«Samsung galaxy s6»**
3. На странице товара нажать **«Add to cart»**
4. Нажать **«OK»** в pop-up
5. Нажать кнопку **«Cart»** в шапке сайта

## Ожидаемый результат

В корзине отображается **единственный** элемент **«Samsung galaxy s6»**.

Если в корзине 0 товаров, больше одного товара или название товара не совпадает — тест считается **проваленным**.

## 🛠 Технологии

| Технология | Версия | Зачем используется |
|---|---|---|
| **Python** | 3.9+ | Язык, на котором написан тест |
| **Playwright** | 1.40+ | Управляет браузером (открывает сайт, кликает, читает текст) |
| **Chromium** | (идут с Playwright) | Движок браузера, в котором выполняется тест |

> **Почему Playwright, а не Selenium?**
> Playwright — более современный инструмент: сам ждёт загрузки элементов, поддерживает «умные» локаторы по ролям (role), автоматически обрабатывает pop-up, а его `expect` умеет ждать с таймаутом. Кода получается меньше, а надёжности — больше.

## Установка

### 1. Убедись, что установлен Python 3.9+

Открой терминал (PowerShell / CMD / bash) и выполни:

```bash
python --version
```

Ожидаемый вывод: `Python 3.9.x` или выше. Если Python не установлен — скачай с https://www.python.org/downloads/.

### 2. Перейди в папку с проектом

```bash
cd путь/до/папки/с/VK-QA.py
```

### 3. (Рекомендуется) Создай виртуальное окружение

**Виртуальное окружение** — это «отдельная песочница» для зависимостей проекта. Чтобы библиотеки одного проекта не конфликтовали с другим.

```bash
python -m venv .venv
```

Активируй его:

- **Windows (PowerShell):**
  ```powershell
  .venv\Scripts\Activate.ps1
  ```
- **Windows (CMD):**
  ```cmd
  .venv\Scripts\activate.bat
  ```
- **macOS / Linux:**
  ```bash
  source .venv/bin/activate
  ```

После активации в начале строки терминала появится `(.venv)` — значит, всё ок.

### 4. Установи зависимости

```bash
pip install -r requirements.txt
```

### 5. Установи браузер для Playwright

Playwright не использует твой установленный Chrome — у него **свой** Chromium. Скачать его нужно один раз:

```bash
python -m playwright install chromium
```

 **Важно:** используй именно `python -m playwright ...`, а не `playwright ...`. На Windows команда `playwright` может не находиться в `PATH` — тогда появится ошибка `«Имя "playwright" не распознано»`. Вызов через `python -m` работает всегда.

##  Что происходит при запуске

1. **Стартует Playwright** — поднимается «движок» управления браузером.
2. **Запускается Chromium** — открывается реальное окно браузера.
3. **Создаётся «контекст»** — чистый профиль (свои куки, история).
4. **Открывается вкладка** — через неё выполняются все действия.
5. **Выполняются шаги сценария** (см. раздел ниже).
6. **Проверяется результат** — в корзине ровно 1 строка с правильным названием.
7. **Закрываются браузер и контекст** — в блоке `finally`, то есть **в любом случае**, даже при ошибке.

## Как это работает — разбор по шагам

### Шаг 1. Открытие сайта

```python
page.goto("https://www.demoblaze.com/", wait_until="domcontentloaded")
page.wait_for_selector(".card-title a", timeout=15000)
```

- `goto` — «перейди по адресу».
- `wait_until="domcontentloaded"` — дождись, пока загрузится **базовый HTML** (быстрее, чем ждать все картинки).
- `wait_for_selector(".card-title a")` — дождись появления **хотя бы одной карточки товара**. Без этого кликнуть было бы не по чему: сайт подгружает товары через JavaScript.

### Шаг 2. Клик по товару

```python
page.get_by_role("link", name="Samsung galaxy s6", exact=True).click()
```

- `get_by_role("link", ...)` — ищи **ссылку** (`<a>`).
- `name="Samsung galaxy s6"` — с **таким текстом**.
- `exact=True` — **точное** совпадение. Защита от того, чтобы случайно не кликнуть по «Samsung galaxy s6 Edge» или другому похожему товару.
- `.click()` — кликни.

### Шаг 3. Add to cart + обработка pop-up

```python
page.once("dialog", handle_dialog)
page.get_by_role("link", name="Add to cart", exact=True).click()
```

- `page.once("dialog", handle_dialog)` — «**подпишись на событие** появления pop-up **один раз**». Когда появится — вызови функцию `handle_dialog`.
- `handle_dialog` (см. ниже) — вызывает `dialog.accept()` (нажимает «OK») и сохраняет текст сообщения.
- `.click()` — кликаем по «Add to cart», что **вызывает** pop-up. Playwright автоматически передаёт событие в наш обработчик.

### Шаг 4. Проверка pop-up

```python
if "text" not in dialog_message:
    raise AssertionError("Pop-up не появился после 'Add to cart'")
if "Product added" not in dialog_message["text"]:
    raise AssertionError(f"Неожиданное сообщение: {dialog_message['text']}")
```

- Проверяем, что pop-up **действительно был** (иначе словарь `dialog_message` остался бы пустым).
- Проверяем, что его текст **содержит** `"Product added"` — то есть товар действительно добавлен.

### Шаг 5. Клик по «Cart»

```python
page.get_by_role("link", name="Cart", exact=True).click()
```

- `exact=True` — **обязательно**. Без этого Playwright нашёл бы **два** элемента: `<a>Cart</a>` в шапке и `<a>Add to cart</a>` на странице товара (там тоже есть подстрока «Cart»). Это привело бы к ошибке **strict mode violation**.

### Проверка ожидаемого результата

```python
rows = page.locator("#tbodyid tr")
if rows.count() != 1:
    raise AssertionError(f"Ожидался 1 товар, найдено: {rows.count()}")

expect(rows.first).to_contain_text("Samsung galaxy s6")
```

- `#tbodyid tr` — **все строки** в таблице корзины (`tbodyid` — id таблицы).
- `rows.count()` — сколько их.
- Если **не 1** — падаем с ошибкой.
- `expect(...).to_contain_text(...)` — Playwright «умная» проверка: если текста нет, она **подождёт** до 5 секунд (на случай, если страница ещё догружается), а потом упадёт.

## Обработка ошибок

В коде есть **три уровня защиты**:

1. **`try / except / finally`** вокруг всего теста:
   - `try` — «попробуй выполнить шаги».
   - `except` — «если где-то упало, выведи причину в консоль, но не "сломай" программу».
   - `finally` — «в любом случае закрой браузер» (иначе процессы Chromium могут остаться в памяти).

2. **Скриншот при падении**: в блоке `except` вызывается `page.screenshot(path="failure_screenshot.png", full_page=True)` — сохраняет **всю страницу целиком**. Это очень помогает понять, на каком шаге что-то пошло не так.

3. **Внутренний `try/except`** вокруг скриншота — на случай, если браузер уже закрыт и скриншот снять нельзя. Тогда просто пропускаем.

## Возможные проблемы и решения

### 1. `playwright: Имя "playwright" не распознано`

**Причина:** каталог `Scripts` Python не добавлен в `PATH`.

**Решение:** используй вызов через модуль:
```bash
python -m playwright install chromium
```

Либо добавь в `PATH` папку (обычно `C:\Users\<имя>\AppData\Local\Programs\Python\Python3X\Scripts`).

### 2. `Executable doesn't exist at ...`

**Причина:** не выполнен `playwright install chromium`.

**Решение:**
```bash
python -m playwright install chromium
```

### 3. `Locator.click: strict mode violation`

**Причина:** локатор находит **больше одного** элемента. Playwright защищает от случайного клика.

**Решение:** уточни локатор — добавь `exact=True`, `nth=0`, используй `#id` или комбинируй селекторы.

### 4. `Timeout 15000ms exceeded`

**Причина:** элемент не появился за 15 секунд.

**Возможные причины:**
- Медленный интернет → увеличь `timeout` (например, до `30000`).
- Сайт поменял вёрстку → обнови селектор.
- Pop-up не появился → проверь, что в блоке `page.once` обработчик корректен.

### 5. Браузер не закрывается после падения

**Причина:** процесс был убит (Ctrl+C) до блока `finally`.

**Решение:** вручную заверши процессы `chrome.exe` через диспетчер задач.

### 6. `Process finished with exit code 0`, но ничего не вывелось

**Причина:** в файле **не было** блока `if __name__ == "__main__":`. Функция была объявлена, но не вызвана.

**Решение:** убедись, что в конце файла есть:
```python
if __name__ == "__main__":
    success = run_test()
    raise SystemExit(0 if success else 1)
```

## Словарь терминов

| Термин | Простыми словами |
|---|---|
| **Playwright** | Библиотека, которая управляет браузером из кода |
| **Браузер / Chromium** | Программа, которая открывает сайты |
| **Контекст** | «Профиль пользователя» в браузере (свои куки, история) |
| **Вкладка (`page`)** | Один открытый сайт внутри контекста |
| **Локатор** | «Правило поиска» элемента на странице |
| **Селектор** | Строка, описывающая элемент: `#id`, `.class`, `tag` |
| **Strict mode** | Режим Playwright, в котором действие падает, если найдено >1 элемента |
| **Pop-up / dialog** | Всплывающее окно (alert), например «Product added» |
| **`expect`** | «Умная» проверка Playwright, умеет ждать |
| **`wait_for_selector`** | «Дождись появления элемента» |
| **`headless`** | Режим без окна (в фоне). `False` — с окном |
| **`slow_mo`** | Замедление действий (мс) для наглядности |
| **`try/except/finally`** | Конструкция для обработки ошибок и гарантированной очистки |
| **Exit code** | Код завершения программы: 0 — успех, 1 — ошибка |
| **`__name__ == "__main__"`** | Проверка «файл запущен напрямую, а не импортирован» |
